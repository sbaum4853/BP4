Part 1 · Breadboard refresher

How your breadboard connects

Columns

The short rows of 5 holes are connected inside by a metal strip. Anything plugged into the same column is connected. We'll call columns by letters like A, B, C. These are just names for "pick an empty column."

Rails

The long lines along the edge are connected all the way across. We use two: the blue (–) rail for ground, and the red (+) rail next to it for 3.3 V.

Your jumpers: the female end (the socket) slides onto the ESP32's pin. The male end (the pin) pushes into the breadboard. Your ESP32 stays off the breadboard.
Unplug the USB cable before you start, and keep it unplugged until a step says to plug it in.
Step 1 of 3 · Power rails

Ground and 3.3 V

1
Find the ESP32 pin labeled GND. Put the female end of a jumper on it. Push the male end into the blue (–) rail.
2
Find the pin labeled 3V3. Put a jumper on it. Push the male end into the red (+) rail right next to the blue one.
3V3, not VIN or 5V. They're different pins. The sensor must get 3.3 V, or it can damage the ESP32.

Part 2 · Code recap

How your node thinks

measureRoom()

Runs once in setup(). Averages 50 light readings to learn how bright the room is, then sets a HIT line and a lower RESET line.

lightHit()

Returns true once, when a new beam rises above the HIT line. Won't count again until the light drops below RESET.

loop()

Asks three questions every pass, never waiting: Time to attack? Hit in time? Too slow? It uses millis() for every clock.

Quick check: why does the node calibrate itself instead of using a fixed number like 2000?
Right. A window seat and a shadowy corner read very differently.

Run the Lesson 3 node

Want to prove your whole rebuild works before we change anything? Upload last lesson's node and defend it once with your flashlight.

const int sensorPin = 34;
const int ledPin = 23;
const unsigned long windowMs = 2000;

int ambient = 0;
int hitLevel = 0;
int resetLevel = 0;
bool beamOn = false;

bool armed = false;
unsigned long nextAttackTime = 0;
unsigned long armedTime = 0;
int blocked = 0;
int escaped = 0;

int measureRoom() {
  long total = 0;
  for (int i = 0; i < 50; i++) {
    total += analogRead(sensorPin);
    delay(20);
  }
  return total / 50;
}

bool lightHit() {
  int level = analogRead(sensorPin);
  bool hit = false;
  if (!beamOn && level > hitLevel) {
    beamOn = true;
    hit = true;
  }
  if (beamOn && level < resetLevel) {
    beamOn = false;
  }
  return hit;
}

void setup() {
  Serial.begin(115200);
  pinMode(ledPin, OUTPUT);
  Serial.println("Calibrating... keep flashlights away!");
  ambient = measureRoom();
  hitLevel = ambient + (4095 - ambient) / 2;
  resetLevel = ambient + (4095 - ambient) / 4;
  randomSeed(esp_random());
  nextAttackTime = millis() + random(2000, 5000);
  Serial.println("Node online. Defend it!");
}

void loop() {
  bool hit = lightHit();
  unsigned long now = millis();

  if (!armed && now >= nextAttackTime) {
    armed = true;
    armedTime = now;
    digitalWrite(ledPin, HIGH);
    Serial.println("!!! NODE UNDER ATTACK !!!");
  }

  if (armed && hit) {
    armed = false;
    digitalWrite(ledPin, LOW);
    blocked++;
    Serial.print("BLOCKED in ");
    Serial.print(now - armedTime);
    Serial.println(" ms");
    nextAttackTime = now + random(2000, 5000);
  }

  if (armed && now - armedTime > windowMs) {
    armed = false;
    digitalWrite(ledPin, LOW);
    escaped++;
    Serial.println("ESCAPED into an Antcar!");
    nextAttackTime = now + random(2000, 5000);
  }
}
Part 3 · The problem

The LED has no drama.

When your node is attacked, its LED just... turns on. Is there plenty of time, or is the clock almost out? You can't tell.

Game designers call a signal like this a tell: a movie bomb that beeps faster, a health bar that flashes when low. Today the node gets one: slow pulsing when the attack starts, frantic pulsing when time's almost up.

The catch

A pin can only be ON or OFF.

To pulse, the LED has to fade smoothly between dim and bright. But an ESP32 output pin only has two settings: 3.3 V or 0 V. There's no "half."

So how do you make an LED look half as bright? You cheat, by being fast.

Build 1 · fake brightness by hand

Blink it faster and faster

const int ledPin = 23;
int onMs = 100;    // how long ON each cycle
int offMs = 100;   // how long OFF each cycle

void setup() {
  pinMode(ledPin, OUTPUT);
}

void loop() {
  digitalWrite(ledPin, HIGH);
  delay(onMs);
  digitalWrite(ledPin, LOW);
  delay(offMs);
}

What just happened

PWM: Pulse Width Modulation

Switch the LED on and off faster than about 60 times a second, and your eye can't see the flicker. It blends the flashes into a steady glow. How bright the glow looks depends on what fraction of the time the LED is on.

That fraction is the duty cycle. 1 ms on and 9 ms off = 10% duty = dim. 9 on and 1 off = 90% duty = bright. Changing the width of the ON pulse to control power is Pulse Width Modulation.

Try it

PWM simulator

Start slow and watch the LED blink. Then drag the speed up past about 60 Hz and watch the blinking turn into a steady glow. Then change the duty cycle.

The easy way

analogWrite(pin, 0–255)

You don't have to switch the pin yourself. The ESP32 has hardware built just for PWM. You tell it a brightness, and it does the fast switching on its own, about 1,000 times a second, while your program keeps running.

analogWrite(ledPin, 0);     // 0% duty: off
analogWrite(ledPin, 64);    // 25%: dim
analogWrite(ledPin, 128);   // 50%: medium
analogWrite(ledPin, 255);   // 100%: full brightness
Rule: once you analogWrite a pin, keep using analogWrite for it. Use 0 for off and 255 for fully on. Mixing in digitalWrite on the same pin can confuse the ESP32's PWM hardware.
Coming soon: PWM isn't just for LEDs. It's how the Antcars will control motor speed. Same trick: switch the power on and off fast, and the motor feels the average.
Build 2 · breathing, no delay()

Brightness from the clock

A node can't take naps, so no delay(). Instead, we calculate the brightness from millis() every pass through loop().

const int ledPin = 23;
const unsigned long period = 2000;   // one full breath every 2 seconds

void setup() {
  analogWrite(ledPin, 0);
}

void loop() {
  unsigned long t = millis() % period;   // where we are in this breath: 0 to 1999

  int brightness;
  if (t < period / 2) {
    brightness = map(t, 0, period / 2, 0, 255);        // first half: getting brighter
  } else {
    brightness = map(t, period / 2, period, 255, 0);   // second half: getting dimmer
  }

  analogWrite(ledPin, brightness);
}
Build 2 · how it works

Two new tools: % and map()

% (modulo)

The remainder after dividing. millis() % 2000 counts 0, 1, 2 … 1999, then starts over at 0, forever.

It's clock arithmetic: 14:00 is 2 o'clock because 14 % 12 = 2.

map(value, fromLow, fromHigh, toLow, toHigh)

Converts a number from one range to another. map(t, 0, 1000, 0, 255): t = 0 gives 0, t = 500 gives 127, t = 1000 gives 255.

Try it: change period to 500, then to 5000. Write in your notebook how the breathing changes. Bonus: what number makes it look like a heartbeat?
Build 3 · the threat LED

Faster as time runs out

While the node is armed, it pulses. The pulse rate starts slow and climbs as time runs out. We track a value called urgency: 0.0 when the attack starts, 1.0 when time is up.

The spinning dial: picture a dial that goes around once per pulse. Each pass through loop(), we nudge it forward. Bigger nudges = faster pulsing. The dial's position, called phase (0.0 to 1.0), decides the brightness: dim at 0, brightest at 0.5, dim again at 1.0.

float is a new variable type: numbers with decimals, like 0.25 or 1.5. We need it because phase and urgency live between 0 and 1.

Build 3 · the code

The complete defense node

New parts are marked // NEW. Everything else is your Lesson 3 node.

const int sensorPin = 34;
const int ledPin = 23;
const unsigned long windowMs = 2000;

int ambient = 0;
int hitLevel = 0;
int resetLevel = 0;
bool beamOn = false;

bool armed = false;
unsigned long nextAttackTime = 0;
unsigned long armedTime = 0;
int blocked = 0;
int escaped = 0;

float phase = 0.0;                 // NEW: where the dial is, 0.0 to 1.0
unsigned long lastPulseUpdate = 0; // NEW: when we last nudged the dial

int measureRoom() {
  long total = 0;
  for (int i = 0; i < 50; i++) {
    total += analogRead(sensorPin);
    delay(20);
  }
  return total / 50;
}

bool lightHit() {
  int level = analogRead(sensorPin);
  bool hit = false;
  if (!beamOn && level > hitLevel) {
    beamOn = true;
    hit = true;
  }
  if (beamOn && level < resetLevel) {
    beamOn = false;
  }
  return hit;
}

// NEW: pulse the LED faster as time runs out
void updateThreatLED(unsigned long now) {
  float urgency = (float)(now - armedTime) / windowMs;  // 0.0 → 1.0
  float pulsesPerSecond = 1.5 + 8.5 * urgency;          // 1.5 → 10

  float seconds = (now - lastPulseUpdate) / 1000.0;     // time since last nudge
  lastPulseUpdate = now;

  phase = phase + pulsesPerSecond * seconds;            // nudge the dial
  if (phase >= 1.0) {
    phase = phase - 1.0;                                // went all the way around
  }

  int brightness;
  if (phase < 0.5) {
    brightness = phase * 2 * 255;                       // getting brighter
  } else {
    brightness = (1.0 - phase) * 2 * 255;               // getting dimmer
  }
  analogWrite(ledPin, brightness);
}

void setup() {
  Serial.begin(115200);
  analogWrite(ledPin, 0);                               // NEW: analogWrite only
  Serial.println("Calibrating... keep flashlights away!");
  ambient = measureRoom();
  hitLevel = ambient + (4095 - ambient) / 2;
  resetLevel = ambient + (4095 - ambient) / 4;
  randomSeed(esp_random());
  nextAttackTime = millis() + random(2000, 5000);
  Serial.println("Node online. Defend it!");
}

void loop() {
  bool hit = lightHit();
  unsigned long now = millis();

  if (!armed && now >= nextAttackTime) {
    armed = true;
    armedTime = now;
    phase = 0.5;                  // NEW: start at the brightest point
    lastPulseUpdate = now;        // NEW
    Serial.println("!!! NODE UNDER ATTACK !!!");
  }

  if (armed) {
    updateThreatLED(now);         // NEW
  }

  if (armed && hit) {
    armed = false;
    analogWrite(ledPin, 0);       // NEW: was digitalWrite
    blocked++;
    Serial.print("BLOCKED in ");
    Serial.print(now - armedTime);
    Serial.println(" ms");
    nextAttackTime = now + random(2000, 5000);
  }

  if (armed && now - armedTime > windowMs) {
    armed = false;
    analogWrite(ledPin, 0);       // NEW: was digitalWrite
    escaped++;
    Serial.println("ESCAPED into an Antcar!");
    nextAttackTime = now + random(2000, 5000);
  }
}
Build 3 · what changed

Only the LED got smarter.

CodeWhat it does
(float)(now - armedTime) / windowMsFraction of the window used up. (float) forces decimal math. Without it, 1000 / 2000 would round down to 0.
1.5 + 8.5 * urgencyAt urgency 0: 1.5 pulses/sec. At urgency 1: 1.5 + 8.5 = 10 pulses/sec.
phase + pulsesPerSecond * secondsNudge the dial forward. A faster pulse rate means a bigger nudge.
phase = 0.5 at attack startBegin at full brightness, so you notice the attack instantly.
analogWrite(ledPin, 0)Turn off with PWM, not digitalWrite. Remember the rule.
The detection, calibration, timing, and scoring are untouched. We added one function and called it from one place. That's how real programs grow.
